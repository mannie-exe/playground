# 2D painting and UI composition

The contract is ui::PaintContext, not SDL_Surface. UI layout produces boxes and
local geometry; a painter consumes those operations on a compatible target.
[GPU.md](GPU.md) owns the frame/resource/runtime contract; [3D.md](3D.md) owns
scene rendering. [UI contracts](../ui/CONTRACTS.md) define node responsibilities.

## Availability and boundary

The concrete painter is sdl::SurfacePainter, managed by SurfaceRenderBackend for
window rendering or directly for offscreen work. It implements current UI drawing
on CPU surfaces. There is no GPU PaintContext implementation yet. A recording/test
painter can implement the same abstract interface without SDL.

Painting does not measure content, mutate application state, poll events or present
the window. AppHost owns RenderBackend; a RenderFrame lends its paint2D() context
to the app, which forwards it to its root/session. Never store that context in a
node or retain it after the frame. The renderer must outlive the frame.

## PaintContext API

Declarations: [PaintContext.hpp](../../include/ui/PaintContext.hpp).
These signatures are public virtual operations; argument values use project math.

| Operation | Meaning / required behavior |
|---|---|
| save() / restore() noexcept | Nest drawing-state scopes; restore prior transform/clip state, not pixels |
| translate(Vec2f) | Compose local translation into drawing coordinates |
| transform(Transform2D) | Compose an affine transform; default supports translation only and rejects other transforms |
| clip(Rect) / clipRounded(RoundedRect) | Intersect current drawing coverage with the transformed shape |
| fill(Rect, ColorRGBA8) | Fill local geometry |
| fillRounded(RoundedRect, ColorRGBA8) | Fill rounded geometry |
| strokeRounded(RoundedRect, Insets, ColorRGBA8) | Paint border coverage with side widths |
| paintRoundedBox(RoundedRect, Insets, ColorRGBA8, optional<ColorRGBA8>) | Joined fill/border coverage; avoid double-compositing shared antialiased edges |
| drawImage(const PaintImageHandle&, Rect sourcePixels, Rect destination, ImagePaint) | Sample a retained image into local logical geometry with tint/sampling |
| pixelScale() const noexcept → Vec2f | Positive logical-to-output density; default {1,1} |
| imagePreparer() noexcept → ImagePreparer* | Optional borrowed realization service; null means identity preparation |
| beginLayer(Rect, float opacity) / endLayer() | Composite the group's output once at its opacity |
| cancelLayer() noexcept | Abandon unfinished group state during unwinding |
| capture(Rect, Vec2f scale, draw callback) → PaintImageHandle | Produce a reusable subtree raster/image at the requested density |

save/restore/translate/clip/fill are required overrides. Most extended operations
have explicit throwing defaults, not permissive no-ops. A minimal painter is not
automatically compatible with every UI node. There is no capability-enumeration
API yet; verify the operations a composition requires when choosing a backend.

PaintScope calls save/restore. LayerScope calls beginLayer and requires finish()
to complete; otherwise destruction calls cancelLayer. A drawing exception must
not strand transformed/clipped state for subsequent work. Pixel writes already
made are not rolled back. Group opacity is not equivalent to applying opacity
individually to overlapping children.

capture's callback is borrowed for the call and receives a compatible context;
do not retain the callback for later execution. Children may already have been
prepared for the original backend, so capture must not silently switch resource
domains. Deferred backends retain image handles for the duration their recorded
work needs them, rather than retaining only raw resource pointers.
Successful capture returns a non-null image with finite, positive pixel dimensions.
Layer rejects malformed results without committing its cache or budget reservation;
the caller may retry. Allocation/backend failures may also throw.

## Coordinates and numerical conventions

| Space | Units / origin | Owner |
|---|---|---|
| Root viewport | Logical units; +X right, +Y down | Host environment |
| Child border bounds | Parent-local logical units | Parent arrangement |
| Local content geometry | Node-local units, after padding/border inset | Node/content policy |
| Visual transform | Affine local-to-parent mapping | VisualProps and painter scopes |
| Image source rectangle | Source image pixels | Content crop/fit |
| Target raster | Physical pixels | Backend/frame |

Source and destination rectangles are different responsibilities. Cropping selects
source pixels; ContentFit and alignment choose a destination inside the assigned
box. Moving a box does not itself require reloading its asset. Density changes may
require text/SVG rerasterization even when logical dimensions are unchanged.

Use the actual drawable/logical size ratio, not guessed DPI. Account for density
once in painting. Preparation composes ancestor affine transforms before deriving
resource density; Layer's rasterScale can deliberately request additional pixels.
Transform2D is affine, not a camera/projection. Perspective belongs to a scene
renderer, not a z field appended to every UI rectangle.

Geometry is finite at API boundaries. Rectangular containment is half-open for
input/layout. Pixel adapters choose rounding and must round shared edges from the
same boundaries. Singular visual transforms draw no subtree and are non-hittable.
Hit testing uses the matching inverse transform and clip shapes.

<a id="image-sources"></a>
## Image and resource contract

PaintImageHandle is shared immutable image identity. ImagePaint holds
tint={255,255,255,255} and sampling=Linear; Nearest is also supported. Tint modulates
the result, not shared source pixels. Source dimensions come from pixelSize(); the
assigned destination remains independent. Invalid crops or incompatible backend
images are errors, not automatic format/device conversion during paint.

To adapt the current registry's decoded surface at the host/resource boundary:

```cpp
#include <platform/sdl/SurfacePaintImage.hpp>
#include <support/AssetRegistry.hpp>

playground::ui::PaintImageHandle loadImageForUI(
    AssetRegistry &assets, const std::string &resolvedPath) {
  return playground::sdl::makeSurfaceImage(assets.getImage(resolvedPath));
}
```

The adapter wraps shared ownership without copying pixels. SurfacePaintImage's
premultiplied argument describes existing pixel representation; setting the flag
does not convert colors. Published source pixels must not be edited in place.
See [GPU resource contracts](GPU.md#resource-contracts) for preparation and caching.

Text and Vector currently produce CPU source images. Their existing wrapping,
fitting, alignment, truncation and SVG style semantics remain unchanged when
images are uploaded. Rendering glyph atlases or vector paths directly is a separate
future provider/painter integration, not an automatic effect of switching backends.

## Retained layers and failure behavior

Node layout caches, AssetRegistry results, Layer caches and backend realizations
have different keys/lifetimes. Layout or paint changes below a Layer invalidate
its captured image; an unchanged subtree can reuse it. Dropping a cache does not
detach children or reset their interaction state.

The root's raster reservation defaults to 64 MiB; each Layer has its own policy
and byte limit. SurfacePainter's temporary composition budget defaults separately
to 64 MiB. Those estimates are not total RAM/GPU budgets. Optional cache refusal
draws uncached; required group composition may fail rather than change its visual
meaning. A future device switch must discard/rebuild incompatible layer images.

Resources are prepared before painting. Failed preparation leaves Text/Image/Vector
unready and can be retried. State scopes unwind on paint errors, but visible pixels
or already-submitted device operations need not be transactional. The current host
does not catch and recover individual frame failures.

## Current SDL adapter and AppHost usage

Sources: [SurfacePainter.hpp](../../include/platform/sdl/SurfacePainter.hpp),
[SurfaceRenderBackend.hpp](../../include/platform/sdl/SurfaceRenderBackend.hpp),
[UISession.hpp](../../include/platform/sdl/UISession.hpp),
[SDLInput.hpp](../../include/platform/sdl/SDLInput.hpp),
[SDLGeometry.hpp](../../include/platform/sdl/SDLGeometry.hpp).

SurfaceRenderBackend borrows Window's native window, queries drawable dimensions,
and reacquires its current SDL surface for each frame. Window creation itself no
longer acquires a surface. The backend clears and presents; resizing must occur
outside a live frame. A minimized/empty target yields no frame. Software frames
return null from scene3D().

`RenderFrameProps::settings.resolutionScale` controls whole-frame target resolution.
At 1 the target is the window surface. Other supported scales allocate/reuse an
offscreen target and composite it to the current window surface on present.
The painter reports actual target density. This can soften text/UI as well as
images; separate scene-only scaling is not implemented. Layout, native window
coordinates and input remain independent of this raster multiplier.

SurfacePainter supports rectangles/rounded shapes, affine rotation/shear/reflection,
transformed rectangular/rounded clips, nearest/linear image sampling, tint, group
opacity and raster capture. Shared surface blend/modulation state is scoped and
restored. Sampling/composition handles premultiplied alpha. Axis-aligned operations
use native fast paths; other affine paths have bounded per-pixel coverage work
(currently 4×4 edge coverage). That cost is a software implementation choice, not
a promise every backend must execute the same algorithm or be pixel-identical.

The current session adapter provides:

| API | Responsibility |
|---|---|
| synchronize(WindowMetrics, ViewportProps) | Resolve Reflow/FixedCanvas viewport and density, then flush layout |
| handleEvent(const SDL_Event&) → EventResult | Translate supported native input, route UIEvent, map result |
| update(float seconds) | Forward root runtime work |
| render(PaintContext&) | Flush layout, prepare with painter density/image service, then paint |
| root() | Access the owned retained root |
| clear() | Remove root content; not a blanket cancellation of app-owned jobs/services |

Within an existing IApp, the integration remains small:

```cpp
// Member fragments; the surrounding IApp provides its normal info/lifecycle.
playground::sdl::UISession _ui;

void render(AppContext &ctx, playground::rendering::RenderFrame &frame) override {
  _ui.synchronize(ctx.windowMetrics(), ctx.presentation().viewport);
  _ui.render(frame.paint2D());
}
```

Synchronize before event routing too when the environment can have changed.
Native mouse positions are in window coordinates. Touch first maps from normalized
coordinates to window coordinates; both then use the inverse viewport mapping.
Painting uses the corresponding forward transform/clip. Synthetic touch-mouse events are ignored. This is
independent of SDL_Renderer coordinate-conversion helpers, which are not the
surface backend in use here. Geometry conversion, native comparisons and native
formatters remain under platform/sdl, not in core layout values.

UISession is optional: a host may own UIRoot directly, as demonstrated by
[the UI guide](../ui/GUIDE.md). Do not mix manual environment policies with a
session that overwrites them on synchronization. The convenience session currently
provides sizing/density, not setters for every environment field.

See [window/viewport contracts](../platform/WINDOWING.md) for system DPI, content
fitting, centering/display selection, and [settings](../platform/SETTINGS.md) for
the runtime values resolved by AppHost. UI nodes do not access preferences files.

## Backend acceptance and future work

Before declaring another painter compatible, assess: shape/image alpha, state
restoration, transformed nested clips, ordering, source crops, tint/filtering,
text/SVG density, group opacity, retained capture, resource lifetime and resize.
An unsupported operation must be rejected or handled by a deliberate documented
fallback. Passing a GPU image to SurfacePainter is not such a fallback.

Idle/damage rendering remains planned: exposure, invalidated old/new bounds,
overlap-correct repaint, animation/asset wakeups and presentation must be coordinated.
Current AppHost clears/draws/presents full frames. Retained nodes alone do not make
the host idle, and needsPaint alone is insufficient to decide what a window needs.

Focused tests include ui_render_backend, ui_affine_shapes, ui_layer_cache,
ui_content_resources and ui_image_preparation; see [TESTING.md](../ui/TESTING.md).
Software offscreen checks do not establish cross-backend color conformance or GPU
execution. Future backends should reuse the semantic tests with backend-specific
tolerances and opt-in device requirements.

Native API background retained from the original UI notes:
[surface blitting](https://wiki.libsdl.org/SDL3/SDL_BlitSurfaceScaled) and
[SDL_Renderer event-coordinate conversion](https://wiki.libsdl.org/SDL3/SDL_ConvertEventToRenderCoordinates).
The latter belongs to SDL_Renderer, not the SurfacePainter input path.
