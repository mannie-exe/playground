# Scene rendering and 3D contracts

The project implements an owned scene, camera math, checked object handles,
software and GPU unlit triangle renderers, and a SceneView UI bridge. Camera
controllers, lighting/PBR and physics are separate application/engine extensions.

The [2D painter](2D.md) remains 2D. [GPU.md](GPU.md) defines frame/device ownership.
UI layout is documented separately under [../ui](../ui/REFERENCE.md).

## Role in the runtime

```text
application model/world
    → camera + mesh draw descriptions
    → RenderFrame::scene3D() (optional)
    → same-backend PaintImageHandle
    → 2D composition / Image node
```

A scene service renders a view, not an application or UI hierarchy. An application
owns its simulation/model and decides which objects are visible. A UI composition
owns the viewport's logical rectangle and user interaction. The backend owns the
physical render target, passes and completion lifetime.

Scene output can be displayed inside a UI Image without giving every Button a
camera. Conversely, projecting a UI panel into a world would require separate
ray-to-panel input mapping and panel render-target ownership. Neither direction
implies that ordinary layout needs a third coordinate.

## Available geometry and camera API

Source: [Geometry3D.hpp](../../include/math/Geometry3D.hpp), linked through
playground_math. These types do not include SDL or a third-party math library.

| Value/function | Contract |
|---|---|
| Vec3f / Vec4f | Float component values; exact equality; Vec4f carries homogeneous w |
| Vec3f +, −, * float; dot/cross | Basic vector arithmetic; ordinary floating-point semantics |
| normalized(Vec3f) | Unit direction; reject zero or nonfinite inputs |
| isFinite | Vector/matrix component validation |
| Matrix4 | Identity by default; 16 column-major floats; checked at(row,column) |
| Matrix4 × Matrix4 / Matrix4 × Vec4f | Column-vector composition; reject nonfinite/unrepresentable float results |
| translation(Vec3f) / scaling(Vec3f) | Finite affine matrices; scale may be zero/negative |
| Quaternion / normalizedRotation / axisAngle | Identity by default; normalize valid rotations; reject zero/nonfinite quaternions and axes; radians |
| Quaternion multiplication / rotation | Hamilton composition; a * b applies b then a; normalized rotation matrix |
| Transform3D::matrix() | Local translation * rotation * scale; defaults to identity |
| inverse(Matrix4) | Pivoted double-precision elimination; reject singular/nonfinite inputs and unrepresentable float results |
| transformPoint | Homogeneous point transform and divide; reject zero W |
| transformDirection | Affine direction transform, excluding translation |
| transformNormal | Affine inverse-transpose followed by normalization; reject singular models |
| perspectiveLH(fovRadians, aspect, nearPlane, farPlane) | Vertical FOV in (0,π), positive aspect/near, far > near |
| orthographicLH(width, height, nearPlane, farPlane) | Positive extents, near ≥ 0, far > near |
| lookAtLH(eye, target, up={0,1,0}) | Finite camera basis; distinct eye/target and nonparallel up/forward |

Conventions are part of the contract:

| Choice | Convention |
|---|---|
| Handedness | Left-handed camera convention |
| Axes | +Y up, camera forward +Z |
| Matrix storage | Column-major; storage does not by itself determine handedness |
| Multiplication | Column vectors: clip = projection × view × model × position |
| Depth | Normalized device depth [0,1] |
| Perspective | Divide clip xyz by w after projection; do not discard w first |
| Position versus direction | Homogeneous w=1 versus w=0; translation affects positions only |
| UI relation | UI +Y down is distinct; renderer/viewport conversion owns the bridge |

World units have no built-in meters/centimeters policy. Projection maps camera
space, not layout units; application models choose physical scale. Negative scales
can reverse winding and zero scales can collapse geometry. Arithmetic permitting
them does not establish a culling/normal-transform policy for a renderer.

Positive axis-angle rotation follows the cross-product/right-hand rule (+Z rotates
+X toward +Y); camera handedness does not silently change that algebra convention.
Nearly singular matrices can remain ill-conditioned even when inversion returns
finite values. There is no condition-number estimate. pickingRay unprojects a
normalized viewport position using inverse projection/view; it is not a controller.
Public math storage has no SIMD alignment or GPU buffer-layout guarantee.

## Scene submission API

Source: [SceneRenderer.hpp](../../include/scene/SceneRenderer.hpp), linked through
playground_scene.

| Type/API | Fields and meaning |
|---|---|
| Vertex3D | position; normal={0,0,1}; uv={0,0} |
| MeshData | Mutable authoring vertex/index arrays; validate() |
| Mesh / makeMesh(MeshData) | Validates once, owns immutable geometry and cached local bounds; read-only data()/bounds() |
| MeshHandle | shared_ptr<const Mesh>; published geometry cannot be modified through a mutable Mesh alias |
| MaterialProps | baseColor=white; optional baseColorImage; alpha=Opaque/Mask/Blend, cutoff=.5; doubleSided=true; nearest/linear sampling and clamp/repeat/mirrored addressing; unlit, not PBR |
| MeshDraw | Required mesh handle, material, model matrix (identity by default) |
| CameraView | view and projection matrices (identity defaults, not automatic cameras) |
| SceneRenderProps | camera, requested pixelSize and clearColor; not the UI node's props |
| validate(view, span<const MeshDraw>) | Check target dimensions, finite matrices, non-null meshes, material semantics and transformed bounds; geometry was validated at mesh construction |
| orderedDraws(camera, draws, TransparentOrder) | Stable opaque/mask partition followed by camera-space back-to-front blended objects, or preserved blended submission order |
| SceneRenderer::render(view, draws) → PaintImageHandle | Render a same-backend sampleable view image; retain/copy inputs needed by submitted work |

Aggregate fields without member defaults are not enforced required constructor
arguments in C++. Supply meaningful sizes/colors explicitly; call validation at
the submission boundary. A default CameraView contains identity matrices, not a
useful automatically configured perspective camera.

Validation rejects empty mesh data, incomplete indexed triangles and out-of-range
indices. An empty draw list is allowed for a clear-only view. Validation does not
prove a camera is invertible, normals are unit length, triangles are nondegenerate,
or material images belong to a particular device. A concrete renderer must enforce
its additional resource/format/topology requirements.

## Borrowing, submission and composition

RenderFrame::scene3D() returns a borrowed service or null. Both shipped backends
provide one. Optional GPU scene pipelines can initialize lazily; required scene
capability is prepared during backend activation.
Check before using an arbitrary backend; unsupported 3D must not appear successful.
The service must not escape its frame or be invoked from arbitrary worker threads.

```cpp
#include <rendering/RenderBackend.hpp>

playground::rendering::PaintImageHandle renderScenePreview(
    playground::rendering::RenderFrame &frame,
    const playground::scene::SceneRenderProps &view,
    std::span<const playground::scene::MeshDraw> draws) {
  auto *scene = frame.scene3D();
  if (!scene)
    throw std::logic_error("Current backend has no scene renderer");
  playground::scene::validate(view, draws);
  return scene->render(view, draws);
}
```

This works with software and GPU frames. The virtual interface cannot force subclass
validation by itself; implementations are responsible for validating submissions.

The span and view reference are borrowed only for the call. Deferred work must copy
descriptions and retain mesh/image ownership. Mesh exposes no mutation after
construction; image providers likewise promise immutable source pixels. Do not
return a dangling view of a transient swapchain texture as a reusable image.

Render scene outputs before recording their consuming 2D pass. If assigning the
result to an Image node, do that before UI preparation/painting; do not mutate the
UI tree from a paint callback. The backends produce independent output images and
submit GPU producers before consumers, avoiding attachment feedback. The interface
does not provide a render graph or an automatic hazard scheduler.

The output's physical pixel size is requested by SceneRenderProps, independently of
its logical UI box. ui::SceneView uses its content box for camera aspect, actual
composed pixel density for target extent, and an additional resolutionScale in
(0,4]. Output is cached by scene revision, physical extent and renderer identity;
setProps/applyPatch invalidates authored changes. Camera projection still uses the
logical aspect when independent X/Y pixel densities differ.

## Ownership and scene API

Scene3D owns records, not simulation or GPU objects. ObjectId contains scene identity,
slot and generation. create, props, setProps, applyPatch, setParent and remove reject
stale/foreign handles. Parenting rejects cycles; removing an object removes its
descendants. Parent visibility suppresses descendants. Local Transform3D values
derive world matrices; reparenting preserves local, not world, transforms.

ObjectProps contains transform, optional mesh, material and visibility. ObjectPatch
uses optional overrides; an engaged null mesh clears it. snapshot() retains immutable
mesh/image handles independently of later object deletion. Scene3D is noncopyable and
nonmovable so its identity is stable. Mutation/snapshot/picking are owner-thread APIs.
Author geometry in MeshData, then publish with makeMesh. To change geometry, build
another mesh and patch the object handle. Source content and identity remain
stable while owned; an idle GPU realization can be evicted and recreated under
the backend's residency policy without invalidating live resource handles.

Child adjacency makes subtree traversal proportional to its descendants; detaching
from a parent's child vector also scans siblings, and growing the free list may
allocate. Retired slots are reused with new generations. World matrices, inherited visibility
and drawable snapshots are cached per scene revision. A rebuild walks each occupied
record once without recursion; snapshot() returns owned copies, so later mutations
do not alter an already published submission. A change currently rebuilds the scene
cache, not only the affected subtree. The cache is owner-thread state, not a lock-free
or concurrently mutable scene.

CameraProps contains eye/target/up, vertical FOV in radians, near/far, and optional
orthographicHeight. view(aspect) validates and builds CameraView. meshBounds returns
a local AABB; intersect(ray,bounds) handles parallel rays. pickingRay uses normalized
viewport coordinates with +Y down. Scene3D::pick first rejects transformed local
bounds, then checks visible transformed triangles
and returns the nearest geometric hit, independent of texture alpha. It is a
linear object traversal with triangle narrow-phase, not a BVH or pixel-perfect
transparency test.

ui::SceneView owns shared scene access, camera props, preferredSize, clearColor and
resolutionScale, optional aspectRatio and transparentOrder. It prepares the view before painting, never adds a camera to
PaintContext, and participates in normal UI clipping/input routing. An application
maps a routed event into node-local logical coordinates and uses the prepared
viewport's rayAt position to call Scene3D::pick: check `viewport()` before using
`viewport()->rayAt(local)`, since newly constructed or empty views have no viewport.
Do not use window pixels directly.

## Viewport and observer mapping

[SceneViewport.hpp](../../include/scene/SceneViewport.hpp) bridges a camera and a
logical content rectangle. `SceneViewportProps` contains `logicalBounds`,
`pixelScale={1,1}`, `resolutionScale=1`, and optional `aspectRatio`. An explicit
aspect letterboxes centrally; otherwise the camera fills the content rectangle.
`resolveViewport(camera, props)` returns no viewport for empty content and rejects
invalid density, aspect, extents or target-size overflow.

The resolved value contains `contentBounds`, `pixelSize` and `camera`:

- `normalizedPosition(local)` maps the leading-inclusive/trailing-exclusive
  visible content area to [0,1); letterboxes and outside positions return no value.
- `rayAt(local)` unprojects through the camera, with UI +Y down and world +Y up.
- `project(world)` returns logical content coordinates, or no value outside the
  clip volume/behind the eye. The far clip edge may project to the geometric
  trailing boundary, which is intentionally excluded from pointer hit testing.

UI layout owns the outer box and insets. The viewport owns camera aspect and
image placement. The backend owns physical attachment allocation. Unequal X/Y
density changes the pixel dimensions but not logical camera aspect. SceneView
caches by model revision, logical aspect, output extent, scene-renderer domain
and image-preparer domain; changing camera/order props explicitly invalidates it.

`orderedDraws` never changes scene storage order. Opaque/masked objects render
first; blended objects then sort by camera-space bounds-center depth. Stable ties
preserve original order. `TransparentOrder::Submission` retains authored blended
order but still separates opaque/masked objects first. Intersecting translucent
objects cannot generally be resolved by an object sort; this is not
order-independent transparency. Direct `SceneRenderer::render` calls consume the
given order, so callers must invoke ordering or intentionally supply their own.

## Renderer policy

| Concern | Implemented contract |
|---|---|
| Target ownership | Independent immutable output per render; GPU RGBA16_FLOAT plus D32_FLOAT within AllocationLimits; software linear working pixels -> straight sRGB output, capped at 8 Mi pixels |
| Coordinates | +Y-up world, +Y-down image, NDC depth [0,1]; two-sided by default, optional backface culling with negative-determinant model compensation |
| Depth | LESS test; clear 1 with explicit [0,1] clipping; opaque/mask writes, blend does not |
| Materials | Opaque forces alpha 1; Mask discards below cutoff then opaque; Blend source-over in submission order; caller sorts translucent objects back-to-front |
| Geometry | Indexed triangles; nearest/linear material filtering, clamp/repeat/mirror addressing; perspective-correct UVs, immutable mesh upload cache on GPU; degenerate triangles draw nothing |
| Submission | Retained inputs until submission; no active attachment sampled; independent offscreen producers precede composition |
| Interaction | Ray construction and geometric picking supplied; controller policy/capture remains app/UI responsibility |
| World/model | Checked hierarchy and snapshots, not a physics/navigation/ECS scheduler |

Lighting/PBR, shadows, animation/skinning, instancing, physics and neural/simulation
compute are separate features. Nothing in a GPUDevice or Matrix4 automatically
provides them. Implement a small tested scene path before generalizing all of them
into a common scene/component system.

Keep software 2D available as a reference backend. Software 3D and GPU 3D are both
implemented capabilities. A 2D-only
app need not allocate scene resources. AppInfo::rendererRequirements declares requirements;
the backend advertises what actually works. PaintContext stays strictly 2D.
See [shared contracts](CONTRACTS.md) for scene ownership, constraints and staging.

## Static model importing

[ModelImport.hpp](../../include/scene/ModelImport.hpp) provides a CPU-only glTF 2.0
and GLB path using pinned [cgltf 1.15](https://github.com/jkuhlmann/cgltf/releases/tag/v1.15).
The parser dependency is private to the scene module. Public APIs contain only
project values, immutable meshes/images and standard-library types.

| API | Responsibility |
|---|---|
| ModelImportProps | Units per source meter, selected scene and document/parser/resource/geometry limits |
| ModelImportServices | Explicit relative-URI byte resolver and encoded-image decoder; caller supplies access/thread-safety policy |
| importGLTF(document, services, props) | Parse and validate owned static data; no implicit filesystem/network/GPU access |
| ModelAsset | Immutable parent-before-child nodes, local transforms, shared mesh/material primitives and import warnings |
| ModelHandle | Shared const model asset, reusable across scene instances |
| ModelAsset::instantiate(scene, transform, parent) | Adds an instance root, node hierarchy and primitive children; returns root and node handles |
| Scene3D::createBatch | Validates/stages a parent-before-child batch, then atomically commits records; allocation failure preserves the previous scene |
| sdl::loadGLTF(path, props) | Convenience file adapter with PNG/JPEG image decoding and directory-confined relative resource resolution |

Instantiation copies object records, not mesh pixels/vertex buffers. Repeated source
meshes and textures share immutable resources. Batch creation stages the existing
record array, so its initial cost is O(existing records + imported records); this
is an asset activation path, not a per-frame spawn mechanism. Removing the instance
root removes its descendants, while published snapshots keep assets alive.

Coordinates convert from glTF right-handed +Y-up meters to project left-handed
+Y-up units: reflect Z, reverse triangle winding, reflect quaternion orientation,
and scale geometry/translations by unitsPerMeter. UVs remain top-down; selected
TEXCOORD sets and KHR_texture_transform are baked into the imported vertices.
TRS nodes and non-singular, decomposable matrix nodes retain their hierarchy;
sheared or singular matrix-authored nodes are rejected rather than approximated.
Explicit TRS nodes may contain zero scales. Selected default scene (otherwise the
first scene) is imported; sceneIndex overrides it.

Indexed/non-indexed triangles, normals, float/normalized unsigned UVs, base-color
textures/factors, alpha modes, double-sidedness and basic sampler addressing/filtering
are supported. Linear factors are encoded into the current 8-bit base-color type.
Lighting materials deliberately become unlit base-color materials and produce a
warning. Camera/light node transforms are retained without attaching controllers
or lighting systems, also with a warning. Explicit distinct minification/mipmap
policies currently reduce to the magnification filter and report that reduction.
Callers should inspect ModelAsset::warnings(), not assume arbitrary glTF fidelity.

Sparse/compressed geometry, vertex colors, primitive modes other than triangles,
skinning, animation, morph targets, mesh-instancing extensions and unknown required
extensions fail explicitly. KHR_materials_unlit and KHR_texture_transform are the
supported required extensions. Those exclusions do not silently produce a partly
working animated model. Lighting/PBR, shadows and animation remain outside this phase.

The import pipeline bounds input, cgltf allocation, buffer bytes, vertex/index
counts and nodes. It performs division-based accessor/view bounds checks before
upstream validation or reads, addressing the overflow-prone arithmetic described in
[cgltf issue 301](https://github.com/jkuhlmann/cgltf/issues/301); sparse accessors are
rejected before upstream validation. Encoded resource budgets are not decoder peak
memory budgets. The SDL adapter rejects oversized decoded surfaces after decoding;
loading hostile files is not a sandbox/security guarantee. URI canonical confinement
does not eliminate filesystem time-of-check/time-of-use races.

Workers may call importGLTF with worker-safe services and publish the resulting
ModelHandle through the runtime completion queue. Scene instantiation and UI/model
mutation remain owner-thread operations. No GPU object is created during parsing.

## Verification and reading

[geometry3d](../../tests/geometry3d.cpp) checks matrix composition, position versus
direction, camera basis, depth endpoints/aspect, invalid inputs and overflow.
[ui_scene_contracts](../../tests/ui/scene_contracts.cpp) checks submission values
and rejection cases. rendering/scenes.cpp tests hierarchy, clipping, alpha/depth
pixels and SceneView capability failures. [scene_viewport](../../tests/rendering/scene_viewport.cpp)
checks letterboxing, density, project/pick mapping, camera-aware ordering, immutable
mesh publication and cached hierarchy updates. `model_import_files` uses an isolated
temporary directory to verify relative/absolute files, percent-encoded resource
names and rejected escaping/network URIs. Opt-in GPU tests execute Vulkan
unlit rendering and selected readback assertions. Further tests should cover
clipping/depth, winding, transparent overlap, target reuse/resize, input-to-view
mapping and submitted-resource lifetime on the actual backend.

Further reading retained from the design notes:
[PBRT projective cameras](https://www.pbr-book.org/4ed/Cameras_and_Film/Projective_Camera_Models)
and [GLM](https://github.com/g-truc/glm). These are background references, not
dependencies or claims that their conventions match this project's conventions.
